# Unified Agent Skills Setup and Execution Instructions

## Objective

Load, read, and follow the instructions for all five specified agent skills. Use their combined guidance throughout the current task, applying each skill at the appropriate stage. Do not skip a skill because another skill appears to cover similar ground.

## Phase 1 — Load All Required Skills

Run the following commands individually and in order:

### 1. ADHD-Friendly Workflow Management

```bash
npx skills use "https://github.com/ayghri/i-have-adhd" --skill "i-have-adhd"
```

Read and follow the complete generated skill instructions. Apply its guidance to keep the workflow organized, manageable, focused, and easy to follow.

### 2. Agent Skills Usage

```bash
npx skills use "https://github.com/addyosmani/agent-skills" --skill "using-agent-skills"
```

Read and follow the complete generated skill instructions. Use its guidance to understand how to discover, interpret, invoke, and apply skills correctly.

### 3. Skill Discovery

```bash
npx skills use "https://github.com/vercel-labs/skills" --skill "find-skills"
```

Read and follow the complete generated skill instructions. Use its discovery process to identify any additional relevant skills when appropriate, without replacing or skipping any of the five explicitly required skills.

### 4. UI/UX Design Guidance

```bash
npx skills use "https://github.com/nextlevelbuilder/ui-ux-pro-max-skill" --skill "ui-ux-pro-max"
```

Read and follow the complete generated skill instructions. Apply its design, usability, accessibility, visual hierarchy, layout, and implementation guidance whenever relevant to the task.

### 5. Structured Questioning and Requirements Clarification

```bash
npx skills use "https://github.com/mattpocock/skills" --skill "grill-me"
```

Read and follow the complete generated skill instructions. Apply its questioning and requirements-validation process to identify ambiguity, uncover assumptions, and establish a clear direction before making decisions that materially affect the outcome.

## Phase 2 — Capture and Read the Complete Instructions

For every skill:

1. Execute the exact command specified above.
2. Capture its complete terminal output. If the output is long, redirect it to a separate temporary file or use an equivalent method that preserves the entire output.
3. Read the entire captured output, not merely the first screen, a summary, or the last few lines.
4. Identify the skill's required workflow, rules, supporting files, scripts, references, and any additional setup instructions.
5. Open and read all supporting files necessary to understand and apply the skill correctly.
6. Follow any additional instructions generated by the skill, provided they do not conflict with higher-priority instructions or applicable safety requirements.

Use separate temporary files when capturing output to avoid overwriting one skill's instructions with another's. For example:

```bash
/tmp/skill-using-agent-skills.txt
/tmp/skill-i-have-adhd.txt
/tmp/skill-find-skills.txt
/tmp/skill-ui-ux-pro-max.txt
/tmp/skill-grill-me.txt
```

These filenames are examples; use the actual paths and output locations required by the environment and the skills themselves.

Do not assume the initial command output contains the entire skill. If the output directs you to additional documentation or supporting files, read those files before proceeding.

## Phase 3 — Resolve Supporting Files Correctly

Some skills may refer to relative paths, supplementary documentation, scripts, or other resources.

* Determine the supporting-files directory explicitly provided by each skill.
* Resolve that skill's relative paths from its specified supporting-files directory, rather than from the project's root directory or the current working directory by assumption.
* Inspect referenced resources before applying instructions that depend on them.
* Use the relevant skill's own setup and execution conventions.
* Do not invent paths, assume files exist, or silently skip missing dependencies. Verify the available files and report a genuine blocker if a required resource cannot be accessed.

Keep each skill's documentation and supporting files associated with the correct skill so that similarly named resources do not get mixed up.

## Phase 4 — Integrate the Skills Into One Workflow

After reading the required instructions, combine their guidance into a coherent working process:

1. **Understand the task.** Establish the objective, constraints, expected deliverables, and definition of success.
2. **Clarify important assumptions.** Apply the `grill-me` process to uncover consequential ambiguities and validate requirements. Avoid unnecessary questions where the available context already provides the answer.
3. **Organize the work.** Apply the `i-have-adhd` guidance to break complex work into clear, manageable steps, minimize unnecessary context switching, and maintain a visible sense of progress.
4. **Apply skills appropriately.** Use `using-agent-skills` to guide skill selection and execution, and `find-skills` to discover additional relevant capabilities when useful.
5. **Apply UI/UX expertise where relevant.** Use `ui-ux-pro-max` for design-related decisions and implementation, following its actual instructions rather than relying on generic design assumptions.
6. **Execute the task.** Follow the resulting workflow, validate important decisions, and produce the requested deliverable.
7. **Verify the result.** Check the outcome against the requirements and the applicable skill instructions. Resolve issues that can be fixed within the available environment.

The skills should complement one another. Use ADHD-friendly organization throughout the process, apply structured questioning where decisions require clarification, discover additional capabilities when they are genuinely relevant, and use UI/UX guidance when the task involves interface design or implementation.

## Phase 5 — Resolve Conflicts and Handle Blockers

When instructions overlap or conflict:

1. Follow system, developer, and other higher-priority instructions first.
2. Respect applicable safety, security, and environment constraints.
3. Follow the specific skill's instructions for its intended area of responsibility.
4. Reconcile compatible recommendations instead of treating them as mutually exclusive.
5. If an important conflict cannot be resolved, explain the conflict and use the safest approach that preserves the task's main objective.

Do not execute destructive commands, expose secrets, overwrite unrelated work, or make consequential changes outside the task's scope merely because a skill suggests doing so.

If a command fails, inspect the error, determine whether the issue can be resolved safely, and retry when appropriate. Do not report a skill as successfully loaded or applied unless the available output supports that conclusion.

## Phase 6 — Completion Requirements

Before considering the setup complete, verify that:

* [ ] All five specified skill commands have been attempted.
* [ ] The complete output from each command has been captured or otherwise made available.
* [ ] The complete skill instructions have been read.
* [ ] Required supporting files and references have been inspected.
* [ ] Relative paths have been resolved from the appropriate supporting-files directories.
* [ ] The instructions have been integrated into a coherent workflow.
* [ ] Any relevant additional skills discovered through `find-skills` have been evaluated appropriately.
* [ ] Failures, inaccessible resources, or unresolved conflicts have been disclosed honestly.

## Final Instruction

Proceed systematically and complete the setup using the available environment. Do not merely execute the five commands and stop; read the complete outputs, inspect the necessary supporting resources, and follow the generated instructions.

Keep the workflow focused and organized, validate important requirements, and apply the combined skill guidance to the actual task. Avoid unnecessary repetition, assumptions, and unrelated work.

At completion, provide a concise summary of which skills were loaded, which instructions and supporting resources were reviewed, how the guidance was integrated, and any remaining blockers. Distinguish clearly between completed actions and actions that could not be completed or verified.
